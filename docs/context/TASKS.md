# Задачи и roadmap

Этот файл фиксирует актуальное состояние проекта после релиза v0.1.2.
Исторические детали по этапам смотри в `CHANGELOG.md` и Git history.

## Выпущено

### v0.1.0

Статус: выпущено.

- Первая Windows portable preview-сборка.
- Основной legacy-интерфейс.
- Базовая проверка обновлений через публичный GitHub Release.
- Исправление отображения фото на Windows.

### v0.1.1

Статус: выпущено.

- Видимый статус процесса обновления.
- Фильтры и итоги на главном экране "Награды".
- Улучшенный поиск.
- Переходы в справочники из форм.
- Возврат из карточки кавалера обратно на главный экран.
- Telegram-уведомления о релизах.

### v0.1.2

Статус: выпущено.

- Рабочий режим записи.
- Сводная таблица-шахматка по кавалерам и наградам.
- CSV-выгрузка шахматки.
- Открытие каталога кавалера.
- Архивирование материалов кавалера.
- Системный выбор места сохранения для архива, PDF-буклета и CSV.
- Zoom / pan / reset в просмотре фото.
- Вставка фото из буфера обмена, если браузер поддерживает Clipboard API.
- PDF-буклет кавалера.
- Каскадные справочники: страна -> категория -> подкатегория -> наименование.
- Обязательные поля для кавалера, награды и знака.
- Улучшенный поиск: пользовательские колонки, подсказки из базы, возврат к результатам.
- Финальная полировка форм и русские сообщения об ошибках.

## Ближайшее после v0.1.2

- Проверка владельцем после v0.1.2.
- Подтвердить обновление через кнопку "Обновить" на стороне владельца.
- Проверить каскадные справочники, обязательные поля, поиск, шахматку, архив/PDF/CSV сохранение и рабочую запись.
- Собрать новую обратную связь владельца.
- Завести отдельные Linear issues на найденные замечания.

## Backlog

- Backup / Restore в интерфейсе.
- Подключение полной рабочей базы владельца.
- Диагностика данных: битые фото, дубли, пустые номера, некорректные даты, неиспользуемые справочники, файлы без привязки.
- Полировка интерфейса под старую Windows-программу.
- Автоматический перезапуск после обновления.
- Расширенные отчёты и аналитика.
- Windows-установщик.
- PDF для сводной таблицы.
- Очистка отвязанных QA-файлов.
- Убрать пользовательские read-only/write-mode режимы из интерфейса и оставить обычную рабочую программу.

## Правила работы с roadmap

- Linear хранит задачи и статусы.
- `docs/context` хранит постоянную память проекта.
- Git history остаётся фактом изменений.
- Hermes QA подтверждает качество перед релизом.
- Новые задачи после проверки владельцем оформлять отдельными русскими Linear issues.
