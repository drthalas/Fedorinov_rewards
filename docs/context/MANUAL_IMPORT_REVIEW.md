# Ручная проверка импорта (ALE-513)

Раздел: «Обслуживание данных» → «Наполнение данных», текущий экран
`/data-maintenance/enrichment/biographies`. В строках «Требует проверки» кнопка
«Проверить» открывает диалог без ухода со страницы. Закрытие/Escape возвращают
фокус, фильтры и позицию списка; возврат из подтверждения сохраняет ввод.

## Текущий UX — corrective 25.10.2026

Один кавалер за раз, только спорные поля среди `biography`, `birthday`
(1800–1999) и `fio`. Для каждого — два взаимоисключающих варианта: текущее
значение и предложение источника. Невыбранное поле остаётся pending; выбор
текущего отклоняет предложение, выбор источника принимает его. Радиокнопки
не предвыбраны. Рекомендация описывает основание в файле, без процентов.
Название/полная ссылка источника и короткая причина видны возле вариантов.
Полный текст биографии раскрывается без дублирования и доступен целиком.

Одна кнопка «Сохранить изменения» готовит подтверждение, показывающее только
фактические before→after. Данные меняются после отдельного checkbox и
«Подтвердить». «Вернуться к выбору» сохраняет варианты; «Пропустить» не пишет
SQLite. После результата доступны тот же список и следующий нерешённый
кавалер. Решённые строки исключаются из очереди, в том числе после reload;
материальный конфликт личности и невыбранные поля не считаются подтверждёнными.

Предложения года/ФИО читаются из имеющихся сведений источника в файле. Если
варианта нет, он не придумывается. Для изменения года/ФИО нужны источник,
совпадение ФИО либо явное подтверждение личности по награде/номеру и evidence
точной награды. При наличии Трудовой Славы I проверяется именно она и её номер;
другая степень/награда не заменяет это подтверждение. Неподтверждённая личность
блокирует перенос предлагаемых сведений. Настоящий 1945 можно оставить;
подтверждение неизменного года не стирает полную legacy дату рождения.

Технические сведения и audit не занимают первичный экран. История сохранена,
actor нового UI — «Пользователь приложения», без выбора чужого имени.
Подписанная исходная книга, export и обычный импорт не меняются.

Решения до отдельного подтверждения точных before→after не пишут SQLite.
План неизменяемый, подписанный, хранится в существующей TEMP области 7 дней.
При записи `BEGIN IMMEDIATE` повторно проверяет HMAC, все signed identity/awards
и live значения трёх полей. Stale snapshot, смена SQLite/ключа, конфликтующие
планы и concurrent изменения блокируют запись. Существующая биография
заменяется только отдельным принятием и подтверждением конкретного текста.
Дополнительно подписанная revision формы связывает показанные текущие значения
с выбором; изменение между открытием карточки и подготовкой плана требует
повторного открытия. Она не меняет и не переподписывает исходный XLSX.

Долговечный audit сохраняется JSON в существующей таблице
`logs(datetime, action, comment)` атомарно с изменениями полей. Он содержит
before/proposed/decision/after/source/evidence/actor/time, hash файла и ID
операции. Повтор того же подтверждения возвращает прежний результат по ID
операции, не повторяет UPDATE или audit. Ошибка audit откатывает все поля.
Миграций нет: при отсутствии совместимого `logs` ручная проверка блокируется
с конкретным сообщением. Обычный импорт сохраняет прежний контракт.

«История ручной проверки» показывает последние 20 подтверждений, с поиском
по ID, независимо от наличия TEMP preview. История строки остаётся читаемой
после принятого изменения ФИО/года, когда исходный snapshot уже устарел.
Итоги решений видны и после reload preview; они не переклассифицируют обычный
импорт и не выдают rejected/pending поля за сохранённые.

`tests/test_ale513_review_choices.py` и выбранные регрессии

и смешанных решений синтетические. Browser click-flow PASS: настоящий upload,

независимые выборы/pending, skip/next, возврат фокуса/scroll, HMAC и concurrent
