# ALE-513 — единый экран «Проверка и импорт»

## Текущий контракт

`/data-maintenance/enrichment/biographies`: native picker автоматически проверяет
выбранный XLSX. Три вкладки: «Готово к импорту», «Требует решения», «Недостаточно
данных». В каждой по 50 строк, переключение вкладки возвращает на страницу 1.
Счётчики соответствуют строкам каждой вкладки. Принятые, но ещё не импортированные
решения остаются в ручной вкладке зелёными; их можно изменить до общего импорта.
Уже записанные строки исключены из очереди; показано число подтверждённых строк.
В готовых и недостаточных строках нет кнопок действий. Полный текст готовой BIO
раскрывается без отдельного review. Отчётные endpoints сохраняются для совместимости,
но кнопки отчёта/повторной проверки/закрытия файла и нижняя история убраны.

Ручное «Принять решение» создаёт только приватный подписанный план. SQLite не
изменяется. Независимы подтверждение личности, сохранение/замена ФИО и выбор года.
Невыбранное остаётся pending. Изменение уже принятого выбора убирает прежний план
из очереди до нового принятия. Единственная кнопка «Импортировать» внизу показывает
короткую сводку полей/готовых/принятых/пропущенных; точные before→after и источники
раскрываются отдельно. Только финальный checkbox + подтверждение записывает batch.
Нерешённые и недостаточные строки не блокируют безопасные дополнения; подтверждённая
BIO может быть импортирована отдельно от остающегося спорным не-1945 года.

## Правила доказательств и совместимость

Автоматически готовы пустая BIO ≤2500 символов с подтверждённой личностью/источником
и достоверный год вместо исходной заглушки 1945. Настоящий 1945 не меняется. Другой
исходный год остаётся ручным. Существующая непустая BIO никогда не заменяется.
Полное ФИО, точная выбранная награда/степень и номер сверяются с signed identity.
Без номера требуются дополнительные независимые совпадения; одной фамилии/инициалов
или заглушки 1945 недостаточно. Прежний обычный BIO-only «Найдено» импорт остаётся
совместимым по своему signed source/status контракту, без скрытых year updates.

Омиссия дополнительной фамилии в скобках (Ермакова/Зайцева №11095) допускает ручное
решение только при совпадении полного имени без этой фамилии, точной награды и номера,
валидной персональной карточке WarHeroes и проверяемых сведениях источника. Owner
может подтвердить того же кавалера и оставить текущее ФИО независимо. Другие ФИО,
неверная награда/степень/номер, отсутствие доказательств и материальное указание на
другого человека не обходятся подтверждением: такие строки — «Недостаточно данных».
Выбор «Не подтверждаю» исключает источник из импорта и сохраняется в audit.

Обычная выгрузка неизменна: 7 видимых колонок и прежний подписанный hidden sheet.
Новый source year не извлекается из BIO и не подставляется в защищённый исходный год.
Поддержаны существующий развёрнутый формат с отдельными source fields и дополнительный
лист «Предложения» в копии штатной выгрузки: `ID кавалера`, `ФИО в источнике`,
`Год в источнике`, `Награда в источнике`, `Номер в источнике`, `Источник`,
`Подтверждённые факты`; необязательная `Проверка личности`. Неизвестные ID, дубли,
формулы и несовместимые источники отклоняются. Original/snapshot/HMAC не меняются и
не переподписываются. ALE-512 worker, research input/output и scheduler независимы.

## Навигация и безопасность

`sessionStorage` v4 хранит только token/имя файла, вкладку/page/scroll, активную
карточку, pending радио-выбор и signed staging tokens. Сырой XLSX/BIO не сохраняется
в browser storage. В обеих общих оболочках приложения узкий navigation helper меняет
только destination верхней вкладки «Обслуживание данных». После «Кавалеров» она сразу
открывает прежний nested workspace. Без workspace — обычное меню. Верхняя «Назад»
явно открывает меню, сохраняя работу. Выбор нового файла через тот же picker заменяет
workspace; при принятых решениях требуется подтверждение сброса. Invalid/stale файл
сбрасывает resume pointer, не восстанавливает его через pagehide и не создаёт цикл.
Финальный checkbox не запоминается. При возврате сервер заново проверяет решения.

Оригинальный HMAC проверяется до receipts. Только собственные HMAC receipts с тем же
file SHA, snapshot digest и непрерывным expected before→actual after продолжают старую
выгрузку. Это не переписывание snapshot. Чужие изменения person/awards/трёх полей,
подменённая история и чужой installation key блокируют продолжение. Старые receipts
можно проверить по сохранённому signed plan; без доказательства нужна новая выгрузка.
SQLite DATE affinity учитывается только для INTEGER↔четырёхзначного года в проверенной
собственной цепочке. Audit хранит фактические значения после UPDATE.

Batch подписывает точный набор авто-планов и принятых manual plans. Staging v4 нельзя
записать старым per-row commit endpoint. `BEGIN IMMEDIATE` заново проверяет HMAC,
полную frozen identity/награды, все expected fields и версию решения. Обновляется
фиксированный allowlist biography/birthday/fio. Данные, per-person audit и batch receipt
атомарны; ошибка любой строки/audit откатывает всё. Повтор операции идемпотентен.
В audit остаются источник, доказательства, actor/time, решение личности и поля.
Нет миграций, media writes, insert person или смены ID/награды/серийного номера.

## Проверки и handoff

Focused TEMP: manual review, review choices, workspace staging + выбранные обычные
import/export regressions. Browser: automatic upload, три вкладки, 50/page, прямой
возврат с page2 и с pending выбором, header Back, независимые stage без записи,
сводка/финальный импорт, genuine1945, не-1945, alias, HMAC/stale/concurrent и retry.
Фикстуры синтетические, всегда TEMP SQLite/media. Full suite/VM без blocker не нужны.

Текущий ACTIVE разрешает после технического PASS сразу physical feature handoff:
сохранить Owner-изменения, проверить REAL-профиль/writers, свежий SQLite online backup,
остановить только подтверждённый прежний feature runtime, запустить committed HEAD
в Edge с тем же REAL SQLite/media и оставить работающим. Только read-only smoke,
автоматических REAL saves/SQL mutations нет. Public Current BAT/.env/updater,
main/production и ALE-512 не меняются. Финальный STOP — READY FOR OWNER MANUAL QA;
технический PASS не является Owner feature PASS.
