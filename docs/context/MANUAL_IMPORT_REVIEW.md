# Ручная проверка импорта (ALE-513)

Раздел: «Обслуживание данных» → «Наполнение данных», текущий экран
`/data-maintenance/enrichment/biographies`. В строках «Требует проверки» кнопка
«Проверить» открывает диалог без ухода со страницы. Закрытие/Escape возвращают
фокус, фильтры и позицию списка; возврат из подтверждения сохраняет ввод.

Редактируются только предложения `biography`, `birthday` (год 1800–1999), `fio`.
Каждое поле независимо принимается, отклоняется или остаётся на проверке.
Подписанная исходная книга и её identity не меняются. Отсутствующие предложения
ФИО/года вводятся вручную; сведения не выдумываются и внешние страницы не
запрашиваются. Для принятия нужны URL и конкретное evidence. Для года/ФИО
дополнительно подтверждается личная сверка Owner/Сергеем с наградой и номером.
Неподтверждённый вариант фамилии не считается доказательством переименования.

Решения до отдельного подтверждения точных before→after не пишут SQLite.
План неизменяемый, подписанный, хранится в существующей TEMP области 7 дней.
При записи `BEGIN IMMEDIATE` повторно проверяет HMAC, все signed identity/awards
и live значения трёх полей. Stale snapshot, смена SQLite/ключа, конфликтующие
планы и concurrent изменения блокируют запись. Существующая биография
заменяется только отдельным принятием и подтверждением конкретного текста.

Долговечный audit сохраняется JSON в существующей таблице
`logs(datetime, action, comment)` атомарно с изменениями полей. Он содержит
before/proposed/decision/after/source/evidence/actor/time, hash файла и ID
операции. Повтор того же подтверждения возвращает прежний результат по ID
операции, не повторяет UPDATE или audit. Ошибка audit откатывает все поля.
Миграций нет: при отсутствии совместимого `logs` ручная проверка блокируется
с конкретным сообщением. Обычный импорт сохраняет прежний контракт.

«История ручной проверки» показывает последние 20 подтверждений, с поиском
по ID, независимо от наличия TEMP preview. История строки остаётся читаемой
после принятого изменения ФИО/года, когда исходный snapshot уже устарел.
Итоги решений видны и после reload preview; они не переклассифицируют обычный
импорт и не выдают rejected/pending поля за сохранённые.

Focused TEMP проверки: `tests/test_ale513_manual_import_review.py` и регрессии
`tests/test_ale510_biography_enrichment.py`. Фикстуры Ермаковой ID11095, I №725,
Кучкарова №18 (1945→1938), Солнцева №502 (1932→1931) и настоящего 1945 — только
синтетические TEMP данные. Browser acceptance проверяет настоящий upload,
независимые решения, отмену, source validation, фокус, scroll, reload, audit,
обычное сохранение и скачивание XLSX. Full suite по контракту не требуется.

Physical Windows preview, REAL записи, Public Current, candidate и production
не входят в этот шаг. Следующий этап — Owner feature review; physical preview
требует отдельной авторизации Owner.

регрессиями ALE-510 — 53 PASS и один прежний FAIL
