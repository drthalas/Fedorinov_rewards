# ALE-525. Совместимость исследовательской выдачи

Категория и степень выбираются из выбранных наград подписанного snapshot. Листы
доказательств сверяются между собой по ID, SHA-256, URL и данным источника. Явный
контракт v1 задаёт `evidence_category` (`hsu` или `glory-i`) и целочисленный
`evidence_version: 1` в JSON строки предложений и полного доказательства.
Прежние HSU и BIO7 распознаются как соответствующие v1 по подписанному контексту
и известным путям доказательства. Для нового типа нужен свой проверяющий.

Для Славы I путь A сверяет точный номер I степени, связь с фрагментом источника
и ФИО. Путь B сверяет полное ФИО, достоверный год и независимый контекст.
Путь B допускает BIO и сохраняет ФИО и год. На обычном импорте HMAC, исходные
поля, журнал, stale и конкурентные изменения проверяются существующими guards.

Для следующего исследовательского run подготовьте ограниченный пилот
`input.compatibility-pilot.xlsx` штатным исследовательским экспортёром.
Используйте подмножество исходных строк с сохранёнными snapshot и подписями.
Для каждой категории нужен допущенный BIO и недопущенный пример. Общий предел
10 строк на категорию. Целевой SHA берётся из версии, которой воспользуется
получатель. Python с зависимостями и скрипт указываются абсолютными путями в
`config.json` будущего run, в объекте `import_compatibility` с ключами
`python`, `checker`, `sha`. Скрипт находится в целевом checkout по пути
`scripts/check_enrichment_compatibility.py`.

Адаптер `scripts/research_compatibility_hook.py` размещается рядом с entrypoints
будущего run. В `worker_bio7.py` вызов `require_preflight(R, w.cfg)` выполняется
в обработанном `try` перед `w.run()`. В `handoff_final.py` вызов
`require_final(R, cfg, file, sha)` идёт сразу после сверки финальных байтов,
до создания DriveSync, регистрации, перемещения или копирования файла. При
ошибке исключение блокирует соответствующий этап. Эти точки проверяются на
копии research entrypoints. Завершённый BIO7 остаётся в своём архивном run.

Preflight прогоняет пилот экспортёра и создаёт подписанные только TEMP ключом
репрезентативные XLSX для каждой выбранной категории/степени. Реальный импортёр
проверяет положительные и отрицательные примеры от экспорта до preview. Final
требует успешный preflight того же входа и SHA, проверяет неизменность исходных
строк и классифицирует весь финал. Выдача блокируется при неизвестной схеме,
повреждённых доказательствах, нуле допущенных BIO или отказе хотя бы половины
подготовленных BIO в одной группе категории/версии/пути. Отчёты находятся в
`state/import-compatibility/{preflight,final}.json`. Успех final означает
offline compatibility. HMAC и состояние SQLite получателя требуют обычного
preview на его установке. Выполненное исследование сохраняет самостоятельный
статус.
